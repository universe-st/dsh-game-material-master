## 一、要解决的问题

### 1.1 用户现在的困境

想做 45° 俯视（等距）地图的游戏开发者，拿 AI 生成地块时一定会遇到这三件事：

1. **比例不对，拼不上。** 生成的菱形宽高比在 1.0~1.9 之间乱跳，摆进网格不是错位就是留缝。
   而 2:1 等距是**精确的几何关系**，差 2% 就能看出缝。
2. **有厚度，盖住邻居。** 模型很爱给地块画一层深色侧面，拼起来这层侧面会压住旁边一格。
3. **风格不统一。** 草地和石块分开生成，一个偏写实一个偏卡通，拼在一张地图上很别扭。

这三个问题**靠改提示词解决不了**。实测数据（详见技术报告的第三章）：

| 生成方式 | 菱形比例实测范围 | 达标率（\|比例−2\| ≤ 0.05） |
|---|---|---|
| 纯文生图，提示词里写明「2:1 等距」 | 1.68 ~ 1.92 | **0%** |
| 纯文生图，**再加一大段几何约束** | 1.03 ~ 1.55 | **0%** |
| 参考图引导的自由生成 | 1.41 | **0%** |
| **代码给精确菱形模板，AI 只填内容** | **1.987 ~ 2.010** | **100%** |

> 反直觉但已被反复验证：**提示词写得越"认真"，比例越差。**
> 把「26.565°」「宽1000px时高500px」写进提示词，模型会把它当成"技术插画"的线索，
> 转而画出带透视、带厚度的立体块。

### 1.2 本模块给出的答案

**把几何和内容拆开：几何交给代码，内容交给 AI。**

- 代码渲染一张**数学精确**的 2:1 洋红菱形模板（本地，免费，不可变）；
- Seedream 只做一件事：把菱形内部填成指定地貌，并且被反复告知「轮廓不许动」；
- 生成完成后，本地**再量一次**模型实际画的菱形，做仿射规整 + 按数学菱形裁切 —— 双保险；
- 拼图由本地算法完成，变化体随机、跨格贴图、正确的遮挡顺序。

用户看到的差别是：**点击"生成地块"，出来的东西直接就能拼。**

## 二、目标用户与使用场景

### 2.1 目标用户

| 用户 | 诉求 | 本模块怎么满足 |
|---|---|---|
| **独立游戏开发者**（主用户） | 需要一整套风格统一的等距地块做原型或上线 | 一次生成 4 类地形 × N 变体 + 装饰，直接可用 |
| **关卡 / 地图设计者** | 想按自己的想法摆一张地图 | 拼图编辑器：刷子铺地块、放装饰，自由调整 |
| **美术** | 有自己想要的画风，不想被预设绑住 | 每个地块可改提示词、可换参考图、可单独重跑 |

### 2.2 典型场景

**场景 A · 从零做一套地块（最常见）**

> "我要一套中世纪风格的等距地块，草地、土地、石块、灌木，再来几棵树。"

1. 新建项目 → 输入画风描述（"中世纪、明亮饱和、像素画风"）；
2. 系统给出默认地块清单（4 类地形 + 4 类装饰），用户可增删改；
3. 点「生成模板」→ 本地瞬间出一张洋红菱形，先确认几何对；
4. 点「生成全部」→ 8 次生图调用，约 2 分钟；
5. 逐项验收；不满意的单张重跑（只重跑那一张）；
6. 点「拼成地图」→ 立刻看到一张示例地图，确认风格统一、无缝；
7. 不满意画风 → 改一次"统一风格描述" → 全部重跑（**可选**，花钱）。

**场景 B · 已有地图，只补几个地块**

> "我地图差一套岩石和矿洞入口。"

把画风描述和一张已有地块截图作为参考图 → 只生成新增的两类 → 拼图确认能融进原地图。

**场景 C · 用对话驱动（agent 用户）**

> "帮我做一套等距地图地块，然后拼一张 20×20 的地图给我看。"

agent 走固定流程：问参数 → 定审核模式 → 生成模板 → 生成地块 → 逐项验收 → 拼图，
过程中每一步都贴深链接给用户点。

**场景 D · 只想要那张地图**

用户其实不关心单个地块，只想快速得到一张能看的俯视地图。所以**「拼成地图」是一等公民**，
不是附带的预览 —— 它可以反复点、零成本、可换随机种子。

### 2.3 与现有模块的关系

```
sprite（八方向角色）  ─┐
image（单图生成）      ├─ 都是「一张图 → 一批素材」
sequence（序列帧）    ─┤
rig（骨骼动画）       ─┘
                       │
tile（地图地块）      ──── 不同：多个素材 → 一张可拼装的地图
```

- **复用**：同一套 API 配置、同一套审核模式、同一套任务/进度/验收骨架、同一套对话调用面。
- **新增**：模板渲染、菱形测量、仿射规整、拼图算法 —— 全部本地计算，无外部依赖。

## 三、核心设计决策（为什么这样做）

这一节记录**必须保留**的产品级决策。改动它们会破坏可靠性，不是风格问题。

### D1 · 模板由代码渲染，绝不使用 AI 生成的菱形

模板是一张洋红色（`#FF00FF`）实心 2:1 菱形，超采样 4× 后降采样，边缘干净。
菱形宽高严格 2:1，四条边是直线。

**理由**：参考图引导的自由生成达标率 0%。把"画对形状"这件事从 AI 手里拿走，是所有可靠性的来源。

### D2 · 规整（规整到数学菱形）必须保留，不能只靠模板

即使走模板填充，模型仍有 0.2%~0.6% 的漂移、位置也不固定。所以生成后必须：

1. 量出模型**实际画的**菱形（下半部分两条下边做稳健直线拟合）；
2. 仿射变换，把它缩放/平移到标准位置；
3. 按**数学菱形**裁 alpha。

**理由**：只有模板不规整 → 每张位置都不同，拼图会错位。
只有规整不模板 → 模型自由发挥，装饰/侧壁不可控，规整反而要把图拉伸变形。

### D3 · 每个地块可以出多个变体，铺图时按类别随机抽

单个地块铺满一整片时会看出明显的网格重复。变体是打散重复感**唯一的**杠杆。

**理由**：实测铺 5×5 纯土地时，只有 2 个变体就能看出 2×2 重复；加到 3 个变体后消失。

### D4 · 装饰（树、建筑）与地面**分两次生成**

不能让 AI 在一张图里同时画"地面 + 树"。模型画的是一整张画，它不知道你要分两层；
按 y 切层的结果是**树被画两遍**（地面层里有半棵，装饰层里又有一整棵，实测有 alpha 剖面为证）。

所以：

- **地面**走 D1+D2（模板填充 + 规整），几何精确；
- **树 / 巨石**独立生成（白底一张图，无模板），按锚点摆放；
- **建筑**独立生成（2×2 地基网格模板引导），按大菱形下顶点摆放。

**理由**：两层各自干净，谁也不干扰谁。装饰的高度不再受菱形约束。

### D5 · 单元格高度 64×96，菱形只占中间

- 菱形四顶点：上 `(32,32)`、右 `(64,48)`、下 `(32,64)`、左 `(0,48)`；
- 菱形之上留 32px 给高出地面的装饰。

**理由**：树冠、屋顶都在菱形之外。如果单元格只有 64 高，它们会被裁掉或溢出到上一格。

### D6 · 装饰的底部锚点 = 地面上"站得住"的位置

树干底端锚在 `y=54` —— 这是**量出来的**：草坪地块在菱形中轴 `x=32` 处，
不透明像素的 y 范围是 `40.0 .. 53.5`。

- 锚点 `48`（菱形中心）→ 树浮在半空；
- 锚点 `64`（菱形下顶点）→ 树干插到地块前沿之外；
- 锚点 `54` → 树干正好踩在草面上。✅

### D7 · 装饰统一世界尺度

所有独立装饰按「宽度归一化到 40px（≈ 菱形宽的 5/8）」缩放，再压一个高度上限。

**理由**：不统一的话会出现一棵树巨大、一棵树很小，树干粗细也不一致。
代价是拿不到"大树/小树"的尺寸差异 —— 已列入待定问题（见 §12）。

### D8 · 拼图的绘制顺序就是遮挡顺序

按 `(r+c)` 升序绘制。**前面一行的地块天然会盖住后面那格装饰的下半部** ——
这正是等距游戏想要的效果，不需要额外的 z 排序逻辑。

### D9 · 不硬编码任何可能失效的尺寸

模板图的尺寸可能在流程中被缩放。所有几何量都必须**从图里量**（`template_diamond()`），
不允许写死「宽 1884 / 高 942 / 中心 1024」。

**理由**：这条是踩出来的 —— 一次把探针原图从 2048 压到 1536 之后，
硬编码的模板几何失效，地块被裁出透明缺口、拼图能看见网格线，**而且不报任何错**。

## 四、用户流程

### 4.1 主流程

```
┌─ ① 新建项目 ──────────────────────────────────────────────────┐
│  输入：项目名 + 画风描述（可选：参考图）                        │
│  系统带出默认地块清单（4 类地形 + 4 类装饰），用户可增删改       │
│  提问：自动审核 / 每步人工审核                                  │
└───────────────────────────┬───────────────────────────────────┘
                            ▼
┌─ ② 生成模板 ───────────────────── 本地 · 免费 · 秒出 ─────────┐
│  输出：洋红 2:1 菱形模板（每类地块尺寸各一张 / 建筑一张 2×2）    │
│  用户可先看一眼几何对不对。不对说明是 bug，不是模型问题         │
└───────────────────────────┬───────────────────────────────────┘
                            ▼
┌─ ③ 生成地块与装饰 ─────────────── ★真实计费 · 每类可单独重跑 ─┐
│  地形地块：模板填充（洋红菱形 + 内容描述）                      │
│  独立装饰：白底单图（不用模板）                                 │
│  大型建筑：2×2 地基网格模板                                     │
│  生成后自动规整 → 给出几何报告（ratio / 残差 / 是否回退）        │
└───────────────────────────┬───────────────────────────────────┘
                            ▼
┌─ ④ 逐项验收 ─────────────────────────────────────────────────┐
│  每个地块的每个变体都可看大图、打通过、单独重跑                 │
│  auto 模式：agent 自己判完就往下走                              │
│  manual 模式：贴深链接，停下等用户说「通过」                     │
└───────────────────────────┬───────────────────────────────────┘
                            ▼
┌─ ⑤ 拼成地图 ───────────────────── 本地 · 免费 · 可反复 ───────┐
│  两种玩法：                                                     │
│   a) 一键随礼铺一张示例地图（可换随机种子）                     │
│   b) 手动编辑：刷子铺地块 / 放装饰 / 跨格建筑                   │
│  可导出：地图 PNG、地块包（PNG + JSON 布局）                    │
└───────────────────────────────────────────────────────────────┘
```

> 每一步都可以只重做那一步：改提示词只重跑对应地块；改布局只重拼图（零成本）。

### 4.2 反复迭代的实际路径

用户最常见的迭代循环（**全部零成本**，只有换画风才花钱）：

```
拼图 → 觉得重复 → 加变体（★花钱）→ 重新拼
     → 觉得某块地太亮 → 只重跑那一块（★花钱）
     → 觉得布局不好 → 换随机种子 / 手动编辑 → 重新拼（免费）
```

## 五、功能规格

### F1 · 项目与地块清单

**F1.1 新建项目**

| 字段 | 必填 | 默认 | 说明 |
|---|---|---|---|
| 项目名 | ✅ | — | |
| 画风描述 | ✅ | 「像素画风，色彩明快饱和，干净色块，无噪点」 | **追加到每个地块的内容描述之后**。改这一条 = 改整套画风 |
| 参考图 | ❌ | 无 | 有参考图时作为 `image` 传入；同时会让透明背景输出可用（见 F3.3） |
| 单元格尺寸 | ❌ | 64×96 | 宽必须能被 4 整除（菱形半宽要落在整数格上）。高级设置 |

**F1.2 地块清单编辑器**

默认带出 8 项（4 地形 + 4 装饰，见附录 A）。每项可编辑：

| 字段 | 说明 |
|---|---|
| 名称 | 用于文件名与界面显示 |
| 类别 | `terrain` 地面 / `decor` 独立装饰 / `building` 跨格建筑 |
| 占格 | 默认 1×1；建筑为 2×2 |
| 内容描述 | **只描述"菱形里面是什么"**，不描述形状、角度、投影 |
| 变体数 | 默认 2（地形）/ 1（装饰）。范围 1~6 |
| 生成方式 | 默认「模板填充」（地形）/「白底单图」（装饰） |

> 界面上必须给一句常驻提示：**内容描述里不要写形状、角度、透视、字号、坐标**。
> 写了会变差（技术上已被验证）。

### F2 · 模板生成（本地，免费）

**F2.1 生成内容**

| 模板 | 用途 | 尺寸 |
|---|---|---|
| 单格洋红菱形 | 地形地块 | 与生成尺寸同（2048²） |
| 2×2 地基网格 | 大型建筑 | 2048²，含洋红外框 + 红色分格线 |

**F2.2 规格**

- 菱形宽高比**严格 2.0**；四条边为直线；
- 颜色 `#FF00FF`（洋红）—— 最"异类"、最容易被模型完全覆盖；
- 菱形占画布约 92%（`margin=0.92`）；
- 超采样 4× 后降采样，边缘无锯齿；
- **不可由用户改形状**（比例、颜色可做成高级选项，但默认值必须保持）。

**F2.3 为什么先看模板**

模板是**唯一的几何真源**。如果模板本身不对（比例不是 2:1、边不直），
后面所有地块都会错，而且是"看起来正常但拼不上"的错。让用户先看一眼，成本为零。

### F3 · 地块生成（★计费）

**F3.1 地形地块 —— 模板填充**

- 输入：单格洋红菱形模板 + 提示词
- 提示词 = 固定前缀 + 内容描述 + 画风描述
- 固定前缀（不可被用户删除，只能在其后追加）：

```
参考图里那个洋红色菱形就是地块的确切形状与位置。请只把菱形内部填成下面的内容。
硬性要求：菱形的四个顶点、四条边、大小、位置必须与参考图完全一致；
不要改变或描画轮廓，不要加边框、描边、外发光、阴影、厚度、侧面墙、立体底座，
不要旋转、不要缩放、不要裁切、不要把菱形画成方块。
菱形之外的区域必须保持完全透明，不要出现任何其他元素、文字、数字、标记、水印。
输出正方形画布，画面里只有一个菱形。
```

**F3.2 独立装饰 —— 白底单图**

- 输入：**无模板**
- 背景描述写「纯白色」而**不是**请求透明（透明输出要求必须带输入图，纯文生图会直接 400）
- 提示词前缀：

```
画一个斜45度等轴测（isometric）视角的游戏装饰物贴图，正交投影，观察者从画面下方看。
正方形画布，装饰物居中，纯白色背景，画面里只有这一个东西：<内容描述>
```

**F3.3 大型建筑 —— 2×2 地基网格**

- 输入：`build-grid-2048.png`（4 个菱形 + 洋红外框 + 红色分格线）
- 提示词要点：说明这是占 2×2 共 4 格的地基；要求底面贴合地基、四边不出界；
  可以往画面上方长高；**要求把参考图里的洋红外框与红色网格线完全去掉**。
- 规整方式与其他地块不同：**按紧致包围盒等比缩放 + 锚点摆放**，
  不走"精确裁菱形"（建筑的地面投影本来就该压在 4 格地基上）。

**F3.4 生成后可选的自动重试**

规整后检查几何报告，`|ratio − 2| > 0.05` 时自动重跑一次。

- 默认**开启**，最多重跑 1 次；
- 界面显示「第 2 次」标记与两次的比例；
- 重跑仍不达标 → 保留两次结果，标黄，让用户自己选。

**F3.5 单独重跑**

任何单个地块 / 单个变体都可以单独重跑，不影响其他项。

### F4 · 规整（本地，免费，不可跳过）

对每张生成结果执行：

| 步骤 | 做什么 |
|---|---|
| 1. 抠底 | 有 alpha 就信 alpha；没有就用边框众数色**从四边泛洪**找背景（不能用"离背景色远=前景"，草地会全图误判） |
| 2. 清模板残留 | `\|rgb − (255,0,255)\| < 60` 的像素判为洋红残留，一并去掉 |
| 3. 测菱形 | 只量**下半部分**两条下边（装饰在上方会污染拟合），稳健直线拟合求交点得下顶点、极值点得左右顶点 |
| 4. 仿射规整 | 把实测菱形缩放/平移到标准位置（上(32,32) 右(64,48) 下(32,64) 左(0,48)） |
| 5. 裁切 | 按数学菱形裁 alpha，菱形外一律透明 |
| 6. 装饰锚定 | 独立装饰：白底抠除 → 宽归一化 40px → 底部锚点 y=54 |
| 7. 出报告 | `ratio` / `edge_resid` / 是否走了模板回退 |

**几何报告要展示给用户**，但不用解释术语 —— 只显示一个状态：

- `ratio` 落在 `2.000 ± 0.02` → ✅ 正常
- 落在 `± 0.05` → ⚠️ 可用（降采样后的正常量级）
- 超出 `± 0.05` → ❌ 建议重跑（并给出重跑按钮）
- 走了模板回退（测量失败）→ ⚠️ 提示"几何按模板对齐，请目视确认"

### F5 · 拼成地图（本地，免费）

**F5.1 一键随机铺图**

| 参数 | 默认 | 说明 |
|---|---|---|
| 列数 / 行数 | 14 × 14 | 1~64 |
| 随机种子 | 固定值 | 同一种子 + 同一布局 = 逐像素一致的结果 |
| 地形分布 | 全草地 | 可指定"某几块用别的类别"（简单表单：按行×列填类别） |

**F5.2 手动编辑（拼图编辑器）**

| 操作 | 说明 |

## 七、验收标准

### 7.1 几何（硬指标，必须 100% 达标）

以 2048² 生成图、64×96 单元格为基准：

| # | 判据 | 阈值 | 验证方式 |
|---|---|---|---|
| G1 | 规整后地块菱形宽高比 | `\|ratio − 2.0\| ≤ 0.05` | 对规整产物重新测量（**不是**对生成原图测） |
| G2 | 菱形边缘直线度 | 边残差 ≤ 4px（2048² 源图上 ≤ 3px） | 边缘点到拟合直线的最大偏差 |
| G3 | 菱形四顶点位置 | 落在规格位置 `± 1px` | 实测顶点 vs 规格顶点 |
| G4 | 菱形内无透明缺口 | 缺口像素数 = 0 | 对菱形遮罩内区域统计 `alpha < 250` |
| G5 | 菱形外无非透明像素 | 越界像素数 = 0 | 对菱形遮罩外区域统计 `alpha > 8` |

> G4/G5 是"拼图能看见网格线"这类问题的**唯一**有效断言，必须进回归测试。

### 7.2 拼图无缝性

| # | 判据 | 阈值 |
|---|---|---|
| S1 | 同类地块铺 5×5 后，整体 alpha 的"洞" | 0 个透明像素 |
| S2 | 相邻格菱形边界处无缝隙 | 沿菱形边界的对照检查无背景色像素 |
| S3 | 同种子 + 同布局 → 逐像素一致 | 两次渲染完全相等 |

### 7.3 装饰

| # | 判据 | 阈值 |
|---|---|---|
| D1 | 装饰底部锚定在"站得住"的高度 | 树干底端 y 落在 `54 ± 2` |
| D2 | 装饰宽度统一 | 所有独立装饰宽度 = 40 ± 4（或等比缩到高度上限） |
| D3 | 装饰不溢出单元格 | 装饰 bbox 在 `0 ≤ y < CELL_H` 内（允许水平 ±半格） |
| D4 | 遮挡正确 | 前排地块绘制后覆盖后排装饰的下半部 |

### 7.4 可复现性

| # | 判据 |
|---|---|
| R1 | 相同输入 + 相同种子 → 相同产物（拼图必须逐像素一致） |
| R2 | **不允许硬编码任何可能失效的尺寸**；模板几何必须从图里量 |
| R3 | 所有几何参数进入 `_build.json` 报告，可回溯 |

### 7.5 工程自检

沿用仓库既有约定，新增一个 `scripts/verify-tile.mjs`，覆盖上述全部 G/S/D/R 断言 +
规整的边界情况（见 §10）。要求：

- 纯本地、不联网、不花钱；
- 至少包含 1 条**反向验证**的回归测试（去掉修复就失败）——
  对应 D9（硬编码尺寸导致透明缺口），用一张被缩放过的模板构造用例。

### 7.6 产品级验收（给用户看的）

1. 新建 → 生成模板 → 生成 4 类地形 × 2 变体 + 4 装饰 → 拼一张 20×20 地图，全程无手工干预；
2. 整张地图**目视无接缝、无网格线、重复感可接受**；
3. 单个地块重跑不影响其他地块；
4. 换随机种子重拼，零成本、结果不同；
5. 全流程可在对话里驱动（agent 走固定流程，能贴深链接让用户点）。

| # | 不做 | 原因 |

## 十、边界情况与降级

| 场景 | 处理 |
|---|---|
| 模型没画菱形（画成方块 / 圆形） | 测量失败 → 回退到按模板几何规整；报告标 `mode=template`，界面提示"请目视确认" |
| 模型把菱形画得过大 / 过小 | 仿射规整会归一化，正常 |
| 模型没擦干净洋红模板底色 | 规整时按颜色剔除（`\|rgb−(255,0,255)\| < 60`） |
| 模型在菱形外画了东西 | 裁切阶段一律 `alpha=0`，丢弃 |
| 网格 RGBA 输出退化成 RGB | 按边框众数色泛洪抠底，正常处理 |
| 装饰没找到（提示词失败 / 全透明） | 该装饰标失败，不阻塞其他项；建议改提示词重跑 |
| 格子尺寸不是偶数 | 新建时校验并报错（菱形半宽必须落在整数格上） |
| 地图过大（> 64×64） | 画布尺寸守卫 + 提示；导出文件大小预估 |
| 只生成了部分地块就点拼图 | **把缺口用已通过的同类变体顶上**，不阻塞；缺类别时才提示先补 |
| 全部地块都失败 | 拼图按钮禁用，指向第 ③ 步 |
| 重复提交 | 沿用现有拦截：同一目标在跑时再点被拒（每次点击都真实计费） |

## 十一、成本与性能预期

### 11.1 成本

| 操作 | 计费 | 说明 |
|---|---|---|
| 生成模板 | **免费** | 本地渲染 |
| 规整 | **免费** | 本地计算 |

**默认一套的成本**：4 类地形 × 2 变体 + 4 装饰 + 1 建筑 = **13 次调用**。

|---|---|
| 模板生成 | < 200ms |

### 11.3 推荐模型

| 用途 | 模型 | 理由 |

**不要用** `doubao-seedream-4-0-*`：忽略透明背景、输出 JPEG，无法抠底。

## 附录 B：术语表

| 术语 | 含义 |
|---|---|
| **等距 / isometric** | 斜 45° 正交投影。地面方格在屏幕上呈现为菱形 |
| **2:1 等距** | 菱形的宽是高的 2 倍。等价于斜边倾角 26.565°。这是本模块唯一的几何规格 |
| **单元格 / cell** | 一个地块的贴图单位，默认 64×96 像素 |
| **菱形 / diamond** | 单元格里地面部分的那个菱形，默认四顶点为 上(32,32) 右(64,48) 下(32,64) 左(0,48) |
| **网格步进** | 相邻格子在屏幕上的位移，默认 `(±32, +16)`。**不等于**单元格尺寸 |
| **模板填充** | 代码给精确菱形 → AI 只填内部内容。本模块的核心方法 |
| **规整** | 生成后量出实际菱形、仿射对齐到标准位置、按数学菱形裁切 |
| **变体** | 同一类地块的多个不同版本，铺图时随机抽，用来打散网格重复感 |
| **独立装饰** | 与地面分开生成、按锚点摆放的图层（树、巨石） |
| **跨格建筑** | 占多个格子（默认 2×2）的单个贴图 |

## 一句话总结

> **用户只需要描述"地里长什么"，不需要操心"菱形是几比几"。
> 形状由代码保证、内容由 AI 填充、拼装由算法完成 —— 出来的东西直接就能用。**
