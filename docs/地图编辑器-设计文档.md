# 地图编辑器（模块六）· 设计文档

> 给维护者看的。面向用户的功能介绍在 [README.md](../README.md)；
> 实现细节与踩坑在 [ENGINEERING.md](ENGINEERING.md) 的「模块六」一节。

## 一、这个模块要解决什么

旧的地图模块（模块五 `tile`）走的是「AI 填菱形 → 本地拼图」：模板由代码渲染、
内容让 Seedream 画、生成完再仿射规整回标准菱形。几何那半边是可靠的，
**内容是概率性的** —— 同一条提示词不同批次画风会漂，非矩形占格经常要重跑。

于是模块六换了一条路线：**不再生成素材，改成导入素材**。

| | 模块五 `tile` | 模块六 `map`（本文） |
|---|---|---|
| 素材来源 | AI 生成（每个变体一次 Seedream 调用） | **导入用户自己的 tileset** |
| 计费 | 生成阶段真实计费 | **零调用、零计费**（全本地） |
| 格网 | 只有 2:1 等距 | 正方形俯视 **或** 2:1 等距 |
| 过渡 | 没有（同族随机抽变体） | `single` / `corner16` / `blob47` 三种自动过渡 |
| 图层 | 单层 + 装饰 + 建筑三条特殊管线 | 多图层 + 每层高度偏移 |
| 导出 | 地块包 + PNG + 自有 JSON | PNG（分层/合并）+ 自有 JSON + **Tiled `.tmj`/`.tsj`** |
| 关系 | 保留，不废弃 | 与模块五并存 |

## 二、四条架构决策

### D1 · 客户端零几何决策

宿主算出**绘制计划**（每项 = `{层, 格号, 图块序号, 目标像素, 不透明度}`），
客户端只做 `drawImage`；导出 PNG 执行的是**同一份计划**。
界面里自己写的几何只有命中测试那四个函数（见 §五）。

为什么必须这样：旧模块把「变体怎么挑、装饰怎么居中、裁剪偏移多少、建筑锚点在哪」
写了两遍（宿主一遍、界面一遍），两边只要有一处口径不同就是
「保存后整体抬高 / 树木悬空 / 点到的格子和涂到的不是同一格」，而且**不报错**。

### D2 · 画布渲染，不是每格 DOM

单个 `<canvas>` + 视口渲染（只画可见 chunk），计划按 32×32 的 chunk 下发。
旧模块每格一个绝对定位节点，14×14 就有 196 个格子 + 三层 `<img>`，大地图必然卡。

### D3 · 宿主是唯一写者

界面只发 op（`paint` / `erase` / `fill` / `rect` / `replace`），宿主应用后回传
**脏 chunk 的计划补丁**。撤销/重做是宿主侧的逆操作日志，界面不维护撤销栈。
旧模块界面自己改草稿、整份提交，于是「预览」与「出图」是两套代码，撤销还会跳步。

### D4 · 派生数据不落盘

跨格占格、垫底地面、掩码解析、包围盒、裁剪偏移全部在渲染时现算。
旧模块为它们存了 `buildings` / `buildingGround` / `map.pixel` 三份缓存，
各自都出过「过期后凭空多出一栋楼」「保存后整体抬高」这类 bug。

## 三、数据模型

```
<DSH_HOME>/game-material-master/map-jobs/<项目 id>/
├── project.json          元数据：网格、图集、族、地图清单、阶段、日志
├── maps/<mapId>.json     单张地图：图层元数据 + 每层数据（0 = 空）
├── tilesets/<tsId>.<ext> 导入的原图（原样保存，不改写）
├── preview/*.png         验收图：切片 contact sheet、掩码覆盖矩阵、地图渲染图
└── export/<地图名>/      导出：map.png / layer-*.png / map.json / map.tmj / *.tsj / *.png
```

```ts
MapProject { id, name, grid, tilesets[], families[], mapIds[], activeMapId, stages, reviewMode?, logs[] }
MapGrid    { kind: "square" | "iso2to1", tileWidth, tileHeight, heightStep }
MapTileset { id, name, file, imageWidth, imageHeight, slice, tiles[] }
MapTile    { id: "t{x}_{y}", rect, name, familyId?, mask?, weight?, tags?, solid?, anchorX?, anchorY? }
MapFamily  { id, name, autotile: "single"|"corner16"|"blob47", priority, edgeMode?, color? }
MapDoc     { id, name, cols, rows, variantSeed, randomVariants, layers[] }
MapLayer   { id, name, kind: "ground"|"decor"|"object"|"overlay", heightOffset, opacity, visible, locked, baseFamilyId? }
图层数据    number[]            // 长度 cols×rows，0 = 空，其余是**全局图块序号**（1-based）
```

三条要点：

1. **图块 id 由矩形派生**（`t{x}_{y}`），不是数组下标 —— 改切分参数之后同一个矩形的
   元数据仍然挂在同一个 id 上。
2. **图层数据存全局图块序号**，序号 = `flatTiles()` 的顺序（图集顺序 → 切分顺序）。
   改切分 / 删图集会让序号平移，宿主会按「图集 id + 图块 id」把每张地图的格子
   重新映射（`remapDocsToIndices`）；对不上的格子清零并计数，**不静默错位**。
3. **全局图块序号与 Tiled gid 是两套编号**：导出时按图集顺序算 `firstgid`，
   gid = `firstgid + 图集内位置`。图集 PNG 会复制进导出目录，`.tsj` 里写裸文件名。

## 四、自动过渡（autotile）

### 三种方案

| 方案 | 掩码位 | 需要覆盖 | 说明 |
|---|---|---|---|
| `single` | —— | 1 | 不做过渡 |
| `corner16` | N=1, E=2, S=4, W=8 | 16 | 只看四邻域 |
| `blob47` | N=1, NE=2, E=4, SE=8, S=16, SW=32, W=64, NW=128 | **47** | 八邻域，角位归约 |

`blob47` 的归约规则：**角位只有在两条相邻边都连通时才有意义**，否则清掉；
两条边连通时**保留输入的角位**。

> ⚠️ 写成「两条边连通就把角位点亮」是错的：那样角位完全由边位决定，
> 规范掩码只剩 16 种，`blob47` 退化成 `corner16`。自检里「恰好 47 个」
> 那条断言就是盯这个的（当年它真的抓到过这个 bug）。

### 优先级规则

一个格子属于族 F 时，某方向的邻居只要满足 `priority(邻居) ≥ priority(F)`
（空单元格算作本层的 `baseFamilyId`）就算连通。于是草地 < 土路 < 水 三族排好
优先级之后，高优先级族会朝低优先级邻居长过渡块 —— 这是 Tiled / Godot 的通行做法。

「在地面上画路」的常见用法因此是：地面层设 `baseFamilyId = 草地`，空单元格渲染草地；
画上土路之后土路朝草地长过渡块。

### 缺掩码时必须回退

缺掩码时**回退到 Hamming 距离最近的已配掩码**（并列取掩码值最小的），
并把回退次数记进计划的 `fallbacks` / 验收报告。绝不留空 —— 留空在网格地图上就是
一个透明洞，而且不报任何错（旧模块的「白色菱形洞」就是这么来的）。

### 掩码怎么配

界面里两条路：逐块点选后「归入某族」并填掩码；或者选中一批块后
**「给某族按顺序分配掩码」**（按 `autotileMasks` 的顺序填满，47 块一次到位）。
掩码全集由**宿主**下发（`view.autotileMasks`），界面不复刻归约表。

## 五、界面必须复刻的那点几何

只有四个函数，都在 `src/client.ts` 的模块六段落里，前缀 `MAP_`：

| 函数 | 用途 | 宿主对应 |
|---|---|---|
| `MAP_pointToCell` | 指针命中 | `mapgeom.pointToCell` |
| `MAP_cellAnchor` | 格子锚点 | `mapgeom.cellAnchor` |
| `MAP_cellTopLeft` | 贴图左上角（含大贴图/自定义锚点） | `mapgeom.cellTopLeft` |
| `MAP_lineCells` | 拖动补间（不能漏格） | `mapdoc.lineCells` |

**判据不是「我推的公式对不对」，而是「与宿主真实现逐点相同」**：
`scripts/verify-map-client.mjs` 拿宿主的真函数对同一组输入逐点比对
（三种网格配置 × 整张地图的采样点 + 边界点），再加上「画布 drawImage 调用序列
== 宿主 buildPlan 计划」这条逐项契约。

除此之外，界面里**不许**出现变体挑选、掩码归约、裁剪包围盒、坐标变换
（`verify-map-client.mjs` 的最后一段会扫源码）。

## 六、导出规范

### 自有 JSON（`map.json`）

```jsonc
{
  "format": "dsh-gem-map@1",
  "grid": { "kind": "square", "tileWidth": 32, "tileHeight": 32, "heightStep": 16 },
  "tilesets": [ { "id", "name", "image", "imageWidth", "slice", "tileCount", "tiles": [ … ] } ],
  "families": [ { "id", "name", "autotile", "priority", "edgeMode" } ],
  "layers":   [ { "id", "name", "kind", "heightOffset", "opacity", "visible", "baseFamilyId", "data": […] } ],
  "legend":   [ { "index", "tilesetId", "id", "rect", "name", "familyId", "mask" } ]
}
```

`layers[].data` 是**语义值**（全局图块序号），不是解析后的贴图 —— 自己格式要能继续改。

### Tiled（`map.tmj` + `<图集>.tsj`）

- `orientation`：`square → orthogonal`、`iso2to1 → isometric`（等距要求
  `tilewidth = 2 × tileheight`，Tiled 的等距就是这个比例）
- `layers[].data` 写**解析后的 gid**（视觉真相），空 = 0
- 层高同时写 `offsety`（Tiled 里能看出层高）与 `properties.heightOffset`（语义不丢）
- `wangsets`：族 → 一个 wangset
  - `blob47` → `type: "mixed"`，`wangid` 8 位，顺序 top / top-right / right /
    bottom-right / bottom / bottom-left / left / top-left（正好是 N/NE/E/SE/S/SW/W/NW）
  - `corner16` → `type: "edge"`，只用下标 0/2/4/6（top / right / bottom / left）
  - 值 0 = 不连通、1 = 连通（对应 `colors[0]`）
- **导出目录自包含**：图集 PNG 复制进导出目录，`image` 写裸文件名

> ⚠️ **待人工确认**：wangsets 的字段形态是按 Tiled 的 JSON 格式文档写的，
> 自检按这个形态逐字段校验；本机无法联网核对 Tiled 本体，**需要人工用 Tiled
> 打开一次 `.tmj` 确认过渡在 Tiled 里也生效**。

### 规模守卫

- 单边 ≤ 512 格；导出图 ≤ 64M 像素（超了明确拒绝，并建议按图层导出 / 降缩放 / 拆图）
- 计划按 32×32 chunk 下发布，一次笔刷最多弄脏 4 个 chunk
- 文档落盘是「最多 2 秒延迟 + 停笔 500ms 补齐」的防抖写入（原子写 + EPERM 重试）

## 七、对话调用面

模块六**全本地**，所以 `game_material_intake` 对 `module=map` **故意不加 API Key 阻塞**。

agent 可以直接画地图：

```js
applyMapOps({ projectId, mapId, ops: [
  { kind: "paint",   layerId: "l0", cells: [{ r: 5, c: 5, tile: 48 }] },   // tile 0 = 清空
  { kind: "fill",    layerId: "l0", r: 0, c: 0, tile: 48 },
  { kind: "rect",    layerId: "l0", r0: 2, c0: 2, r1: 6, c1: 6, tile: 48, filled: true },
  { kind: "replace", layerId: "l0", from: 48, to: 12 }
] })
```

`tile` 用 `getMapProject` 的 `legend[].index`（从 1 开始，0 = 空）。
返回体里带**脏 chunk 的计划补丁**，所以 agent 也能判断「这一笔影响了哪一片」。

## 八、验收标准（可度量）

| # | 判据 | 阈值 | 谁在盯 |
|---|---|---|---|
| A1 | 两种网格的 `pointToCell(cellCenter) === (r,c)` | 100% | `verify-map.mjs` |
| A2 | `blob47` 规范掩码恰好 47 个且幂等 | 精确 47 | `verify-map.mjs`（含反向验证） |
| A3 | 界面 drawImage 序列 == 宿主 buildPlan | 逐项相等 | `verify-map-client.mjs` |
| A4 | 坐标函数与宿主实现逐点一致 | 逐点相等 | `verify-map-client.mjs` |
| A5 | 一次 paint 的脏 chunk ≤ 4 | 断言 | `verify-map-pipeline.mjs` |
| A6 | 同文档两次导出逐字节一致 | `Buffer.equals` | `verify-map-pipeline.mjs` |
| A7 | 导出的 `.tmj`/`.tsj`/`map.json` 自洽 | 逐字段 | `verify-map-pipeline.mjs` |
| A8 | 全量撤销 → 全量重做回到逐项相同的计划 | 完全一致 | `verify-map-pipeline.mjs` |
| A9 | 真机：canvas 截图 == 导出 PNG（scale=1、无缩放） | 逐像素 | **人工 / Playwright** |

## 九、非目标

六边形与 3D 透视；AI 生成或补齐素材（本模块零 AI）；图块翻转/旋转；
动画地块；Tiled 工程**读取**（`.tsj`/`.tmj` 导入）与 XML `.tsx`/`.tmx`；
Godot `.tres`；多张地图合并导出；程序化地形生成。
